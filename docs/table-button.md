# Кнопка «Аналитика» над таблицей объектов

Кнопка принадлежит конкретному списку. Оператор устанавливает фильтр и нажимает «Аналитика». Источником служит `list` из события списка. Флажки в строках на эту кнопку не влияют. Для отдельной операции «Аналитика по выбранным» у Naumen предусмотрена коллекция `subjects`.

## Отчёт одним скриптом

1. На тестовом стенде откройте **Настройка системы → Действия по событиям → Добавить действие**. Название — **Аналитика**, объект — **класс строк таблицы**. Для списка заявок в карточке отдела это класс заявок. Выберите **[Пользовательское событие]**, тип действия **Скрипт**, выполнение **синхронное**. Вставьте [полное тело действия](../groovy/examples/TableAnalyticsButton.groovy) в поле скрипта и сохраните. В группе прав «Пользовательские события» разрешите действие только ролям, которым для всех объектов этого списка доступны тип, статус и, если он включён, выбранный числовой атрибут. Серверное действие может выполняться с повышенными правами.
2. Для таблицы на карточке откройте **Классы → класс владельца карточки → Карточка объекта**. Найдите контент с нужным списком, нажмите его значок настройки. В блоке **Панель действий** выберите **Новая кнопка → Добавить на панель действий**. Укажите название **Аналитика**, вид **Кнопка с подписью**, **Применяется к → к объектам списка**, действие **Аналитика**. Сохраните. Для списка на форме откройте настройки контента этой формы.
3. Войдите как оператор. Отфильтруйте таблицу до известного количества объектов, например семи. Нажмите **Аналитика** — в штатном окне должно быть «Объектов в таблице: 7», а ниже распределения по типам и статусам. Проверьте ещё раз с другим фильтром и с несколькими страницами. Проверьте с ролью, у которой часть объектов скрыта. Для среднего укажите в строке `def metric` код числового атрибута. Отчёт показывает и количество значений, вошедших в среднее. Действие работает самостоятельно.

Если нужная таблица открывается отдельно из меню и её настройки отличаются, для определения места кнопки достаточно увидеть заголовок списка и его панель действий. Строки и адрес страницы можно скрыть.

## Если клиентская Studio уже установлена отдельно

Для панели с графиками в окне оператора должен быть доступен `window.NSDAnalytics`, подключённый разрешённым для установки способом. [Подпись файла кастомизации](customization.md)

[TableStudioAction.groovy](../groovy/integration/TableStudioAction.groovy) использует [AnalyticsPayload.groovy](../groovy/integration/AnalyticsPayload.groovy). После подключения этих классов и проверок доступа замените тело действия вызовом:

```groovy
TableStudioAction.open(list, result, fields, mayReadRow, mayReadField, readProjectedField)
```

`list` и `result` предоставляет пользовательское событие NSD. Остальные четыре аргумента задаёт серверная настройка вашей таблицы:

| Аргумент | Что передать |
|---|---|
| `fields` | Разрешённые коды колонок этого отчёта, например код статуса и длительности. |
| `mayReadRow` | Замыкание, проверяющее право текущего пользователя на объект. |
| `mayReadField` | Замыкание, проверяющее право пользователя на конкретный атрибут этого объекта. |
| `readProjectedField` | Замыкание, возвращающее простое значение разрешённого поля из подготовленной проекции. Для ссылок верните только разрешённые значения. |

Адаптер однократно обрабатывает переданную коллекцию и вызывает документированный для синхронного пользовательского события `result.executeJavaScript(js)`. Клиент получает разрешённые строки и открывает `NSDAnalytics.open` в текущем окне. Поля списка автоматически из интерфейса не извлекаются. Если права пользователя или справочники нужно получать отдельно, подготовьте их пакетно на стороне NSD.

В публичном руководстве для `list` указан предел **1000 объектов**. Метод `list.limitExceeded()` позволяет отличить ровно 1000 строк от усечённой выборки. Если лимит превышен, скрипт предлагает сузить фильтр. Количество 1000 включительно обрабатывается полностью.

## Основание и проверка

Naumen показывает аналогичное действие в примере «Сумма трудозатрат» для списка записей. Имена переменных и методов взяты из публичной документации SMP. Проверены Groovy-скрипт на подставном контексте и вызов панели в Chromium. Проверка на установленной NSD 4.17, включая влияние конкретных фильтров и прав, выполняется на вашем стенде.
