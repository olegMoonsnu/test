# Архитектура

Studio получает снимок разрешённых объектов. SQL Server, Hibernate и очередь задач NSD остаются на стороне платформы. Каждый новый снимок создаёт отдельный Dataset и сбрасывает результаты предыдущих запросов.

| Модуль | Ответственность и основной файл |
|---|---|
| Analytics Core | Жизненный цикл снимка и диспетчер запросов, `core/session.js`, `core/dataset.js` |
| Data Engine | Собственные поля DTO, проекция, счётчик байтов, безопасные пути, `utils/data.js` |
| Schema Engine | Обход всех переданных строк, разрешённая схема, тип mixed для несовместимых значений, `engines/schema.js` |
| Filter Engine | Предикаты дерева AND/OR и выбор элементов диаграммы, `engines/filter.js` |
| Aggregation Engine | Отдельный аккумулятор для каждого типизированного ключа, сортировка и производные показатели, `engines/aggregate.js` |
| Statistics Engine | Меры, квантиль, дисперсия, относительная динамика и выбросы, `engines/statistics.js` |
| Pivot Engine | Разреженные ячейки по префиксам измерений. Предки используют ту же строку один раз, `engines/pivot.js` |
| Chart Engine | Собственный SVG, доступные метки, две оси для heatmap/stacked, `charts/render.js` |
| Dashboard Engine | Исходный дашборд, иерархия для drill-down, размер и порядок, `engines/dashboard.js`, `components/studio.js` |
| Export Engine | Ограниченный экспорт выборки, безопасный текст ячеек, отчёт и изображения, `engines/export.js` |
| UI Engine | Shadow DOM, модальное окно, редакторы, виртуальная таблица и навигация по сводной, `components/` |
| Performance Engine | Кооперативная отмена, пакетный ввод, ограниченные кеши и протокол Worker, `engines/performance.js`, `engines/worker.js` |
| Configuration Manager | Схема версии 1, проверка импорта и разрешённых перечислений, `core/config.js` |
| NSD Integration Adapter | Публичные методы, доверенные функции хоста и точки приёма JSON, `adapters/nsd.js`, `groovy/integration/` |

Путь запроса проходит через нормализацию DTO, построение схемы, выбор индексов, агрегацию и рендер. Общие фильтры и временная выборка с диаграммы объединяются с фильтром виджета через AND. Кеш хранит шесть наборов индексов и 24 результата ограниченного размера. Большие сводные в кеш результатов не попадают.

Начиная с 5 000 строк Studio пробует создать Worker из встроенного исходного кода. Материализованные порции до 512 DTO передаются с подтверждением. Подготовленные строки принадлежат Worker. Таблица запрашивает только видимый диапазон, экспорт получает страницы. При запрете Worker используется тот же движок в главном потоке с передачей управления браузеру. Нативные сортировки синхронны в выбранном потоке. Закрытие уничтожает Worker и DOM; повторное открытие начинает новую сессию.

Сборщик esbuild сначала собирает Worker, затем встраивает его и CSS в один IIFE. Два файла dist — две взаимозаменяемые версии одного приложения. Источники исследования и решения приведены в [research.md](research.md).
