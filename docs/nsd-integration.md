# Подключение к Naumen Service Desk 4.17

Проверены самостоятельный Groovy-код и браузерный мост на синтетических данных. Доступа к установленной NSD 4.17, её правам, журналам JDBC и фактической сигнатуре запуска JavaScript у разработчика не было.

## Серверная операция

1. Определите контекст текущего пользователя в штатной операции. Выберите разрешённый класс, поля и ограниченный диапазон записей. Параметры запроса, список полей и доступ к ссылочным объектам контролирует сервер.
2. Через поддерживаемый в вашей сборке API получите **пакетную проекцию** разрешённых полей. Ограничьте выборку на уровне источника. До сериализации примените объектные и атрибутные права, включая UUID, наименования и ссылки вложенных сущностей. Пустая выборка допустима.
3. Передайте Iterable подготовленных записей и разрешённые коды в [AnalyticsPayload.groovy](../groovy/integration/AnalyticsPayload.groovy). Замыкания отвечают за доступ к строке, доступ к полю и извлечение уже загруженного значения. Разрешайте доступ только при явном true. Вложенные Map должны содержать только разрешённые подполя. Сериализатор не умеет выяснять права NSD.
4. Передайте результат как **отдельный строковый аргумент** зарегистрированному клиентскому обработчику. Пример обработчика находится в [receive.js](../groovy/integration/receive.js). Внутри вызываются JSON.parse и NSDAnalytics.open. Если среда принимает объект аргументом, можно передать массив подготовленных DTO напрямую.
5. На стенде с двумя ролями проверьте различия самих DTO в браузере, затем отчёта, исходных строк, выгрузок и повторного update. Подберите лимит ниже верхней границы по объёму ваших строк и времени серверной операции.

Рабочий пример со списком Map находится в [PrepareOperation.groovy](../groovy/examples/PrepareOperation.groovy). Здесь намеренно отсутствует вымышленная команда выполнения JS. Точка привязки — зарегистрированный обработчик `receiveAnalyticsPayload(payload, trustedOptions)`. Вариант, при котором хост принимает только текст программы, требует отдельного адаптера по документированному транспорту этой установки. Не вставляйте JSON в HTML или в строку исполняемой программы конкатенацией.

## Hibernate, JDBC и рабочий календарь

Доступ к ленивой коллекции, title ссылочного объекта или проверке прав через отдельный запрос для каждой записи может создать N+1. Код сериализации не обращается к БД. Он не может устранить запросы, спрятанные внутри предоставленных замыканий. Материализуйте скаляры, справочники и решение по правам пакетами штатными средствами вашей установки. Сравните число SQL-запросов для 100 и 1 000 записей и время занятости JDBC-соединения на стенде. Заканчивайте работу с серверной транзакцией до открытия дашборда. Изменение фильтров или графиков не запускает Groovy повторно.

Нарушение SLA, просрочку, длительность в рабочем времени и оставшийся регламентный срок рассчитывает хост по рабочему календарю. Демонстрационный генератор явно задаёт синтетические показатели. Гражданский возраст открытого обращения подписан в календарных днях.

## Встраивание и живая карточка

Передайте DOM-элемент как `mount` или используйте модальное окно по умолчанию. Для перехода по UUID передайте доверенный `onOpenObject(row)` с существующей функцией навигации хоста. Альтернатива — разрешённое сервером поле URL того же origin и параметр `urlField`. Для настроенной проекции включите это поле в columns. При передаче UUID и deep link проверьте права и при повторном открытии целевой карточки.
