# Как внедрить NSD Analytics Studio в Naumen Service Desk 4.17

Для обычной кнопки над таблицей со списком объектов используйте [пошаговую настройку действия списка](table-button.md). Она использует описанные в руководстве SMP `list` и `result.executeJavaScript(js)`. Ниже приведён общий вариант подключения для других точек запуска.

Инструкция для Studio **v0.1.0**. Результат внедрения — операция «Аналитика» в списке или карточке NSD. Нажатие открывает модальное окно поверх текущей страницы. Groovy один раз готовит выборку под правами сотрудника, затем браузер сам фильтрует данные, строит графики и сводную.

Начните на тестовом стенде с трёх вымышленных заявок. Для установки достаточно выпущенного JavaScript и существующего механизма клиентских операций. Устанавливать Node.js, npm или новый сервер, создавать таблицы в Microsoft SQL Server либо менять JDBC Pool для Studio не требуется.

## 1. Возьмите файлы из одного релиза

Скачайте и распакуйте [архив v0.1.0](https://github.com/olegMoonsnu/test/releases/download/v0.1.0/nsd-analytics-studio-v0.1.0.zip). Файлы понадобятся в разных местах.

| Файл из архива | Куда и зачем |
|---|---|
| `dist/nsd-analytics.min.js` | В разрешённые **клиентские** ресурсы вашей NSD. Это сама Studio с интерфейсом, стилями и вычислительным движком. |
| `groovy/integration/receive.js` | Туда же, если Groovy передаёт JSON **строкой**. Несмотря на имя каталога, это JavaScript для браузера. |
| `groovy/integration/AnalyticsPayload.groovy` | В доступный операции серверный Groovy-модуль. Класс превращает разрешённые поля в JSON и проверяет размер пакета. |
| `groovy/examples/PrepareOperation.groovy` | Пример использования класса. Содержит вымышленные данные и демонстрационные проверки прав. |
| `demo/index.html` | Можно открыть локально на рабочем ПК для знакомства с интерфейсом. В NSD переносить демо и генератор данных не нужно. |

Если копируете сборку вручную, выполните в корне распакованного архива `sha256sum dist/nsd-analytics.min.js`. Для v0.1.0 ожидается `7e54d842f2b468284580d4e1129be33e770980086cc463bd05a6af4888d1e80c`. Рабочая страница должна загружать файл с внутреннего ресурса организации. Публичное демо предназначено для синтетических данных.

## 2. Подключите Studio на тестовой странице NSD

Возьмите существующую операцию стенда, которая уже умеет запускать JavaScript в браузере. По её образцу создайте операцию «Аналитика» для тестовой роли. Сохраните исходную настройку, если будете редактировать существующую кнопку.

1. Зарегистрируйте `nsd-analytics.min.js` тем способом, которым ваша установка подключает локальный клиентский скрипт. Следом подключите `receive.js` как обычный скрипт, если будете передавать строку JSON.
2. Если штатная настройка принимает HTML, пример ниже показывает порядок загрузки. Пути `/custom/nsd-analytics/...` приведены для примера. Подставьте реальные **URL ресурсов**, которые браузер открывает под тестовой учётной записью. Если настройка принимает тело JavaScript, используйте штатное подключение ресурсов или инициализацию страницы без HTML-тегов.
3. Откройте именно ту карточку или список, где будет кнопка. Проверьте кодом ниже тот же контекст окна, в котором выполняется операция. При использовании iframe это важно.

```html
<script src="/custom/nsd-analytics/nsd-analytics.min.js"></script>
<script src="/custom/nsd-analytics/receive.js"></script>
```

```js
window.NSDAnalytics?.version                // ожидается "0.1.0"
typeof window.NSDAnalytics?.open           // ожидается "function"
typeof window.receiveAnalyticsPayload      // ожидается "function" для строкового моста
```

В публичном руководстве SMP для синхронного пользовательского действия документирован вызов `result.executeJavaScript(js)`. Сверьте его с комплектом документации вашей сборки 4.17 или с рабочим действием на стенде. [Методы результата пользовательского действия](https://www.naumen.ru/docs/sd/nsmp/Content/script/api_scr_user.htm)

## 3. Проверьте кнопку до подключения Groovy

Добавьте этот обработчик в код инициализации клиентской части после загрузки ресурсов из шага 2. Имя `openOperationAnalytics` задаём сами. Обработчик принимает готовый массив либо строку JSON. Настройки отчёта находятся в доверенном клиентском коде.

```js
window.openOperationAnalytics = function (data) {
  const config = {
    title: 'Аналитика заявок',
    columns: [
      { code: 'uuid',     title: 'UUID',                type: 'string' },
      { code: 'status',   title: 'Статус',              type: 'string' },
      { code: 'duration', title: 'Время решения',       type: 'number', unit: 'мин' }
    ],
    widgets: [
      { id: 'count', title: 'Всего заявок', type: 'kpi' },
      { id: 'mean', title: 'Среднее время решения', type: 'kpi',
        measure: { op: 'avg', field: 'duration' } },
      { id: 'statuses', title: 'Заявки по статусам', type: 'bar', dims: ['status'] }
    ]
  };

  if (Array.isArray(data)) {
    return window.NSDAnalytics.open(data, config);
  }
  return window.receiveAnalyticsPayload(data, config);
};
```

В клиентское действие кнопки временно поместите следующий вызов. Кнопка запускает его по нажатию.

```js
window.openOperationAnalytics([
  { uuid: 'demo$1', status: 'Закрыта',  duration: 30 },
  { uuid: 'demo$2', status: 'Закрыта',  duration: 90 },
  { uuid: 'demo$3', status: 'В работе', duration: null }
]);
```

**Ожидаемый результат:** открылось одно окно, URL карточки сохранился. В нём **3 заявки**, среднее **60 мин**, на диаграмме **«Закрыта» — 2**, **«В работе» — 1**. Нажмите столбец «Закрыта» → «Показать исходные объекты». Должны появиться две строки. Если здесь всё работает, подключение интерфейса закончено.

## 4. Соберите тот же пакет на стороне Groovy

Сделайте класс `AnalyticsPayload` доступным скрипту операции штатным для вашей установки способом. Если редактор Groovy допускает классы в том же исходнике, для стендовой проверки можно поместить содержимое файла класса вместе со следующим телом скрипта, оставив импорты в начале. При сообщении `unable to resolve class AnalyticsPayload` проверьте регистрацию класса, его пакет и импорт.

Следующий пример **выполняется на вымышленных данных**. Четвёртая запись имитирует объект другой роли; примечание первой записи имитирует закрытый атрибут. В реальной операции оба решения о доступе должен принимать сервер NSD.

```groovy
def fields = ['uuid', 'status', 'duration', 'note']
def visibleFields = ['uuid', 'status', 'duration']
def batch = [
    [canRead: true,  allowed: visibleFields,
     dto: [uuid: 'demo$1', status: 'Закрыта',  duration: 30, note: 'FIELD_MARKER']],
    [canRead: true,  allowed: visibleFields,
     dto: [uuid: 'demo$2', status: 'Закрыта',  duration: 90]],
    [canRead: true,  allowed: visibleFields,
     dto: [uuid: 'demo$3', status: 'В работе', duration: null]],
    [canRead: false, allowed: visibleFields,
     dto: [uuid: 'ROW_MARKER', status: 'Закрыта', duration: 999]]
]

String payload = AnalyticsPayload.encode(
    batch, fields,
    { row -> row.canRead == true },
    { row, code -> row.allowed?.contains(code) == true },
    { row, code -> row.dto[code] }
)

assert !payload.contains('ROW_MARKER')
assert !payload.contains('FIELD_MARKER')
assert !payload.contains('"note"')
return payload
```

Здесь `return payload` только возвращает строку той части операции, которая вызвала Groovy. Окно откроется после передачи результата клиентскому обработчику.

## 5. Свяжите результат Groovy с нажатием кнопки

Вместо трёх строк из шага 3 передайте результат шага 4. Выберите вариант по **фактическому контракту** вашей работающей операции.

| Что поддерживает ваша операция | Что подключить |
|---|---|
| Вызывает клиентский обработчик и передаёт ему аргумент | Укажите `openOperationAnalytics` как обработчик, а строку `payload` передайте отдельным значением. Если callback уже получает локальную переменную с результатом, его тело — `return window.openOperationAnalytics(result);`, где `result` — реальное имя аргумента. |
| Уже передаёт клиенту массив обычных JS-объектов | В callback выполните `return window.openOperationAnalytics(rows);`. Дополнительный JSON.parse не нужен. Подготовьте только разрешённые объекты и поля до передачи массива. |
| Принимает только текст JavaScript | Сначала подтвердите, что метод действительно предназначен для исполнения доверенного клиентского кода и как журналирует его аргумент. Для стенда ниже есть способ передать JSON внутри фиксированного вызова. Сигнатуру штатного метода возьмите из вашей существующей операции. |

**Для третьего варианта.** Кодирование Base64 сохраняет кириллицу и отделяет данные от синтаксиса JavaScript. Base64 обратим. Если платформа записывает выполняемый текст в общедоступный журнал, выберите отдельный аргумент данных для рабочих объектов. Учтите, что Base64 увеличивает объём примерно на треть, а транспорт NSD может иметь меньший лимит.

Один раз зарегистрируйте в том же клиентском контексте декодер.

```js
window.openOperationAnalyticsBase64 = function (encoded) {
  const maxLength = 4 * Math.ceil(16 * 1024 * 1024 / 3);
  if (typeof encoded !== 'string' || encoded.length > maxLength) {
    throw new Error('Размер пакета превышает лимит или получен неверный тип');
  }
  const bytes = Uint8Array.from(atob(encoded), ch => ch.charCodeAt(0));
  const json = new TextDecoder('utf-8', { fatal: true }).decode(bytes);
  return window.openOperationAnalytics(json);
};
```

В Groovy после получения `payload` и **вместо** `return payload` сформируйте аргумент текстового метода. Этот фрагмент требует Java 8+ и браузера с TextDecoder.

```groovy
String encoded = java.util.Base64.getEncoder().encodeToString(
    payload.getBytes(java.nio.charset.StandardCharsets.UTF_8)
)
String clientCode = "window.openOperationAnalyticsBase64('" + encoded + "');"
// Передайте clientCode в тот же штатный метод, которым эта операция
// уже запускает клиентский JavaScript на вашем стенде.
```

В строку кода попадает только результат стандартного Base64-кодировщика. Не подставляйте туда исходный JSON, заголовок заявки или переданное пользователем имя функции. После подключения выбранного транспорта кнопка должна снова показать **3 / 60 мин / 2 закрытых** уже из серверного результата.

## 6. Подставьте реальную выборку

1. В серверном скрипте замените тестовый `batch` на результат **вашей существующей выборки**. Для пилота удобно взять один тип объектов, ограниченный период и, например, 100 записей. Лимит задайте в самом источнике до загрузки всей коллекции. Отобразите в названии отчёта период или границы выборки, если она охватывает только часть заявок.
2. Сопоставьте корпоративные коды с полями отчёта. `uuid` — строковый идентификатор, `status` — разрешённое название статуса, `duration` — число минут или null. Если длительность хранится в секундах, один раз переведите её в минуты. Значение 0 участвует в среднем, null пропускается.
3. Получите разрешения для **текущего пользователя** на запись и поле, включая UUID и названия связанных объектов. Передайте в `encode` доверенные серверные проверки или заранее вычисленные решения. Проверка видимости кнопки и клиентский список `columns` не ограничивают исходный пакет. Если нужного разрешённого значения нет, пропустите поле или передайте null в соответствии с правилами вашей проекции.
4. Передавайте простые Map, списки и скаляры. Hibernate-объекты и ленивые коллекции целиком сериализовать нельзя. Подготовьте связанные названия и решения о доступе пакетами средствами вашей сборки. Обращение к БД внутри замыкания чтения каждого поля способно создать N+1. Поля в примере `canRead`, `allowed` и `dto` принадлежат демонстрационной структуре.
5. Добавляйте столбцы по мере необходимости. Для SLA передавайте флаг нарушения и рабочую длительность, рассчитанные NSD по календарю. Для открытия карточки можно передать разрешённый URL того же origin через поле `url` и включить его в `columns`, либо задать доверенный `onOpenObject(row)` с действующей навигацией установки. Для размещения в существующем контейнере передайте его DOM-элемент как `mount`. [Настройки и примеры](configuration.md)

## 7. Примите на стенде, затем откройте пилотной группе

| Как проверить | Критерий приёмки |
|---|---|
| Войти под двумя ролями с разными правами на записи **и** поля | Разрешённые количества совпадают со штатным списком для тех же ограничений. У ограниченной роли контрольные закрытые значения отсутствуют в самом пакете, исходных объектах и JSON-экспорте. Используйте для этой проверки синтетические маркеры. |
| Сверить один известный период, одну закрытую и одну открытую заявку | Суммы, единицы и SLA совпадают с источником. Для пустой выборки приходит массив `[]`, открывается пустой отчёт. |
| Сравнить 100 и 1 000 объектов на стенде | Зафиксированы длительность серверной операции, размер пакета и число SQL-запросов доступными средствами мониторинга. Если число запросов растёт примерно на один запрос на объект, проверьте ленивые ссылки и проверки прав. |
| После открытия несколько раз менять фильтр и тип графика | Операция выборки не запускается повторно. Время работы Groovy и JDBC-соединения не зависит от того, сколько пользователь держит окно открытым. |
| Закрыть окно и снова нажать кнопку | Появляется одно окно. Офлайн-демо и синтетическая проверка не заменяют этот тест внутри веб-интерфейса NSD. |

В рабочем контуре подключите те же версии ресурсов, перенесите проверенную операцию и включите её для пилотной роли. При регистрации ресурса используйте версионированное имя или URL, чтобы пользователи получили нужную сборку из кеша. Встроенные пределы примера — 100 000 посещённых строк и 16 МиБ JSON в UTF-8. Рабочий лимит выбирайте по результатам замеров на вашем сервере. [Полный перечень ограничений](performance.md)

## Если кнопка не работает

| Симптом | Где проверить |
|---|---|
| `window.NSDAnalytics` равен undefined | В Network найдите запрос к внутреннему JS. Проверьте HTTP-статус, содержимое ответа и сообщения CSP. Ответ 200 со страницей входа вместо JS тоже указывает на проблему с публикацией ресурса. Проверьте окно или iframe операции. |
| `receiveAnalyticsPayload is not a function` | Проверьте порядок подключения `receive.js` и контекст его видимости. Готовый массив можно передать напрямую в `openOperationAnalytics`. |
| Операция вернула JSON, окно не открылось | Проверьте, выполняется ли клиентский callback после возврата Groovy. Повторите шаг 3, затем шаг 5 на синтетическом пакете. |
| Ошибка JSON.parse или «Ожидается массив объектов» | После **одного** JSON.parse должен получиться массив. Частые причины — двойная сериализация, ответ `{rows:[…]}` вместо массива или Groovy `Map.toString()` вместо JSON. |
| График пустой или среднее неожиданное | На вкладке «Объекты» сверьте коды полей, типы, единицы, null и фильтры. Числовая строка `"90"` не участвует в AVG. |
| Подготовка медленная ещё до появления окна | Отдельно измерьте выборку, проекцию и сериализацию. Сравните SQL-запросы при разных размерах. Ограничьте поля и период на сервере. |

**Откат.** Отключите тестовую или пилотную операцию для роли. В открытой вкладке вызовите `window.NSDAnalytics?.destroy()` либо перезагрузите страницу. Верните сохранённую конфигурацию кнопки и предыдущую версию ресурсов, если это было обновление. Эта схема внедрения не меняет структуру БД.

Примеры из этой инструкции выполнены вне Naumen на Groovy 2.4.21 и Chromium 138. Все три варианта передачи показали 3 заявки, 60 минут и 2 исходные строки при выборе статуса «Закрыта». Штатный вызов JavaScript, регистрация ресурсов, права доступа и нагрузка конкретной NSD 4.17 проверяются на стенде организации.
